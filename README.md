# kbdb-seminar01 — Разворачиваем стек и знакомимся с данными

Курс **«Базы знаний и базы данных»**, кафедра ИУ-1, 3 курс. Семинар 1.
Задание целиком — в [`docs/seminar01.pdf`](docs/seminar01.pdf).

## Быстрый старт

Нужны Docker (Desktop или Engine + Compose) и Git.

```bash
make up        # поднять PostgreSQL с датасетом (первый запуск скачает образ, ~1 мин)
make psql      # консоль psql внутри контейнера
make run       # прогнать sql/seminar01.sql и показать результаты
make reset     # перезагрузить датасет с нуля (снести том)
make down      # остановить
```

Без `make`: команды написаны в `Makefile`, их можно копировать руками.

Подключение из любого SQL-клиента (DBeaver, DataGrip, VS Code):

| параметр | значение |
|---|---|
| host | `localhost` |
| port | `5432` |
| database | `plant` |
| user / password | `student` / `student` |

## Датасет

Условная компрессорная станция: 3 площадки, 7 агрегатов, 18 датчиков, сутки телеметрии
с шагом 1 минута (2 сентября 2026), журнал событий и журнал ремонтов.

| таблица | что хранит |
|---|---|
| `station` | площадка |
| `unit` | агрегат (ГПА, насос, АВО); `id` — текстовый код вида `GPA-2` |
| `sensor` | датчик на агрегате: `kind` (temp / vibration / pressure / load), `tag`, единица измерения |
| `telemetry` | измерения: `ts`, `sensor_id`, `value` |
| `event` | события и аварии: `severity` (info / warning / alarm / unplanned_stop) — данные «как есть» |
| `maintenance` | ремонты и ТО — перенесено из Excel, со всеми последствиями |

Данные сгенерированы детерминированно, у всех в группе они одинаковые. В них намеренно есть
«грязные» места — найти их часть задания.

## Если что-то не так

- **Порт 5432 занят** — в `docker-compose.yml` поменяйте `"5432:5432"` на `"5433:5432"` и подключайтесь к 5433.
- **Контейнер падает** — `make logs`. Чаще всего проблема в правах на папку `sql/init` или в занятом порте.
- **Данные не загрузились** — init-скрипты выполняются только при первом создании тома: `make reset`.
- **Windows** — включите WSL 2 backend в Docker Desktop и держите репозиторий внутри WSL, не в `C:\Users\...`.
